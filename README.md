<h1 align="center">TubeMuse</h1>

<p align="center"><b>一句话找片，打分让它越来越懂你。</b><br/>只服务你一个人的 YouTube 学习助手（Chrome / Firefox 扩展 · Manifest V3）</p>

在侧边栏里用一句话（打字或语音，中英文）说出想看什么。TubeMuse 先把这句话拆成一条条要求给你确认，再结合你的订阅和喜好找视频，每条结果都写明"为什么推给你"。你打 1–10 分，它会告诉你"因为这次打分改了什么"。

它还会记下你每天真正看了什么，每晚写一份学习总结，娱乐过量时轻声提醒一次；也能汇入 X 上与你兴趣相关的热点，每周推荐几个值得关注的新博主；侧边栏还能读你订阅的豆瓣条目的最新评论。

> 🔒 **只读、本地优先**：没有服务器，没有账号体系，所有数据只存在你自己的浏览器里。不改动 YouTube 页面，**永远不会**替你订阅、点赞、评论或发帖。

## ✨ 功能一览

| 功能 | 你会看到什么 |
|---|---|
| **一句话找片** | 打字或语音说出想看什么；"我的理解"逐条列出每个要求以及它怎么落实（已落实 / 近似落实 / 无法满足……），可以改了再搜 |
| **带理由的结果** | 每张结果卡写明"为什么推给你"，并显示时长、发布时间、播放量，以及满足了哪些要求 |
| **打分让它变好** | 打 1–10 分；低分会先问是"理解错了"还是"找错/排错了"，然后告诉你具体改了什么，可撤销 |
| **观看记录** | 自动记下你在 YouTube 上真正看了什么：看完 / 部分观看 / 瞥一眼，以及学习 / 娱乐 / 其他 |
| **每日总结** | 每晚 23:00 生成"今日学了什么 / 值得回看 / 只是路过 / 与近期目标的关联"，可以导出成 Markdown 记忆库 |
| **导师提醒** | 最近 7 天娱乐过多、学习过少时，在侧边栏顶部轻声提醒一次，附一个合你胃口的学习视频 |
| **每周自省** | 本周低分推荐有什么共性，以及系统据你的打分自动改了什么 |
| **X 热点**（可选） | 与你兴趣相关的 X 热点，每条附原文链接，一键转成找片；只在你点"刷新"时花钱，每日花费有上限，超出立即停止 |
| **新博主** | 每周最多推荐 5 个你还没订阅、最近活跃的频道，每个附理由和最近 3 个视频；只能"打开频道"，不提供订阅 |
| **自动字幕**（默认免费） | 给没有原生字幕的 YouTube 视频叠加双语字幕（上一行原文、下一行译文）。**默认关闭**，每个视频由你在侧边栏点一下或按 `Alt+Shift+S` 开启。默认用浏览器自带的语音识别（免费，边说边出字；Chrome 能用，Firefox 只在下载了这个语言的本机语音模型后才能用），也可以改用 OpenAI 转写；回看或拖回去时精确对齐；每日花费有上限 |
| **多语字幕**（免费） | 把视频自带的几种 YouTube 字幕同时叠在播放器底部，一种语言一行（默认：原声语言、English、简体中文；字幕里断开的行接成一行，太长时这一行自动缩小），每种语言按自己的时间轴对准播放进度；视频没有某种语言时用 YouTube 自带的自动翻译补上并标"机翻"。**默认关闭**，在侧边栏 **字幕** 页点一下或按 `Alt+Shift+C` 开启；全屏、剧场模式自动放大 |
| **中文配音**（免费，不联网） | 给一个 YouTube 视频关联你电脑上的中文配音（`.m4a`，例如小宇宙上同一期节目的中文版）：侧边栏 **配音** 页选一次文件，之后打开同一个视频时工具栏图标标出 **中**、侧边栏顶部提示有中文版；点 **开启配音**，中文跟着视频的播放、暂停、拖动进度和倍速走，原声降 20%；偏移手动对齐第一句。中文常比原视频短很多（例如 46 分钟对 1 小时 2 分）：在对不上的地方 **加对齐点**，分段对齐——对齐点之间中文按正常速度放，先说完就停下等画面，说得慢就在下一个对齐点跳过去。**对齐图** 用两条音轨（英文原声、中文配音）画出对齐状态：此刻两边差多少、哪里只有原声、哪里的中文被跳过、照现在的对齐中文在视频哪里放完；在图上左右拖中文就能调这一段。**只跟随播放状态 + 手动偏移 / 对齐点，不做逐句对齐**。配音开着时用 **片段** 录一段，录下的是双语混音（原声 80% + 中文配音）。音频只存在这个浏览器里 |
| **豆瓣评论** | 粘贴豆瓣条目链接即可订阅，侧边栏 **豆瓣** 页以图文卡片展示最新评论（作者、时间、评价星级、正文开头），点"读全文"到豆瓣看完整内容 |
| **小红书** | 在小红书网页版（xiaohongshu.com / rednote.com）的笔记卡片上，作者那一行直接显示发布时间（精确到分钟）；在页面上把笔记或博主收进 TubeMuse、打自定义标签，在侧边栏 **小红书** 页筛选、改名、删除标签。只存在本机，不会在小红书上收藏或关注 |
| **小宇宙** | 在小宇宙网页版（`www.xiaoyuzhoufm.com`）的单集页上听播客：侧边栏 **小宇宙** 页点 **开始字幕**（或 `Alt+Shift+S`），页面底部播放器上方出现中英双语字幕（OpenAI 转写 + 大模型按节目简介校对人名术语、补标点，再译出另一种语言；提前转写，不比声音晚；可只看中文 / 英文）；**生成整集字幕** 后下载 SRT / WebVTT / 纯文本 / Markdown；收藏单集和节目、打标签；**收听记录**；选一段生成 **音频片段 + 字幕的分享快照**（封面、标题、中英字幕引文、真实波形、起止时间），导出图片 / 这段音频、复制链接、交给系统分享。**字幕默认关闭**，花费记在"字幕 $"里 |
| **eMails** | 在 Gmail 里打开文章汇总邮件（如 Medium Daily Digest），侧边栏 **eMails** 页列出里面的文章：点 **评估** 给每篇打 0–10 分并写一句理由，再给这封邮件一段总体结论（一篇值得精读的都没有时说明原因），按"值得精读 / 一般 / 建议跳过"筛选，一键收藏、打标签。只读打开的这一封，不改动邮箱；评过的文章不再花钱 |
| **问 muse** | 看到想问的地方，点侧边栏顶部的 **问 muse**（那个毛绒小人的图，鼠标停上去有说明）：记下这一刻的播放位置（视频不暂停），把平台、链接、标题、作者、播放位置、章节、简介、上下文（位置前后 30 秒的字幕：在 YouTube 上会自己去取视频自带的字幕；别的平台是这条帖子 / 笔记的正文）和你的问题整理成一段文字，你复制后粘贴到 Muse 聊天（muse.ai）里提问。YouTube、小红书、X、酷播、Instagram、抖音、B 站都能用。只生成文字：不替你发送，不调大模型，不花钱 |
| **片段录制** | 边看边录下想要的一段（YouTube 视频（含 Shorts）、小红书笔记详情里的视频、X 帖子里的视频（帖子页，或首页信息流里正在播放、开着声音的那个）、酷播 `www.kubb.tv` 播放页里的视频、Instagram 首页信息流里正在播放、开着声音的视频、抖音精选页、搜索结果里点开的视频，或 B 站 `www.bilibili.com` 播放器里的视频——普通视频、番剧影视、课程、播放列表、活动页都行）：侧边栏 **片段** 页（或 `Alt+Shift+R`）自由录制，或填起点、终点按时间段截取；画面和声音都来自这个视频，YouTube 上可选把字幕烧进画面。广告（X 和 B 站的片头广告、酷播上认不出来的广告除外）、暂停时自动暂停；录完由浏览器存进下载文件夹（Chrome 默认 MP4，Firefox 是 WebM）。**Capture** 一键把当前这一帧按视频真实尺寸存成无损 PNG，同时放进系统剪贴板（切到别的应用直接粘贴）。不经过网络，仅供个人学习 |

<a id="install"></a>

### 1. 安装（只做一次，约 10 分钟）

<a id="download"></a>

#### 1.0（可选）不想自己构建：直接下载安装包

每次有改动合并进 `main`，GitHub 会自动打好安装包，发布在 **[Releases](https://github.com/Anna-SAP/TubeMuse/releases)** 页（最新的一版标着 **Latest**，版本号形如 `0.1.0.137`，越新越大）。用它可以跳过下面的 1.1 和 1.3，不用装 Node.js 和 Git。

| 文件 | 给哪个浏览器 | 怎么装 |
|---|---|---|
| `tubemuse-<版本>-chrome.zip` | Chrome 或其他 Chromium 内核浏览器（**推荐**） | 解压到一个固定的文件夹（以后不要移动、删除它）→ 按 [1.4](#load-extension) 加载这个文件夹（里面直接就是 `manifest.json`） |
| `tubemuse-<版本>-chrome.crx` | Chrome（签过名的安装包） | **Windows / macOS 上的正式版 Chrome 不允许安装 Chrome 应用商店以外的 .crx**（拖进 `chrome://extensions` 会被拒绝或装上后被停用，常见报错 `CRX_REQUIRED_PROOF_MISSING`），这两个系统请用上面的 .zip。用企业策略（`ExtensionInstallForcelist`）部署时可以用它（发布前的自动化测试走的就是这条路） |
| `tubemuse-<版本>-firefox-signed.xpi` | Firefox 149 及以上（**推荐**） | Mozilla 签过名，**永久安装**：`about:addons` → 齿轮 →「从文件安装附加组件…」选它，或直接拖进 Firefox 窗口。发布后几分钟内才出现（要等 Mozilla 签名）。安装时 Firefox 会列出[数据收集声明](#data-consent) |
| `tubemuse-<版本>-firefox.xpi` | Firefox 149 及以上 | 未签名的同一份内容：按 [1.5](#firefox) 第 3 步临时载入（第 1 步的构建跳过），重启 Firefox 后要重新载入 |

装好以后：

- **Google Cloud**：照 [1.2](#google-cloud) 配置。"已获授权的重定向 URI"填 Releases 页上写的 **授权回跳地址**（Chrome 版是 `https://<扩展ID>.chromiumapp.org/`，装好后设置页「2. YouTube 账号」里也显示；Firefox 版固定不变，见 [1.5](#firefox)）。Chrome 版的扩展 ID 由发布用的签名密钥决定，每一版都一样，所以更新版本时 Google Cloud 里不用改。
- **OAuth Client ID**：发布的安装包里**不带** Client ID（仓库是公开的），装好后在设置页「2. YouTube 账号」的 **OAuth Client ID** 框里填一次（和 Client Secret 一样只存在本机），然后照 [第 2 步](#setup) 继续。
- **更新**：Chrome 下载新版本的 .zip，解压**覆盖到原来那个文件夹**，在 `chrome://extensions` 点 TubeMuse 卡片上的刷新按钮，本机数据保留；Firefox 安装新版本的 `-signed.xpi`，原地升级（临时载入的则重新载入新的 `.xpi`）。

#### 1.1 下载代码、安装依赖、生成扩展 ID

```bash
git clone https://github.com/Anna-SAP/TubeMuse.git
```

```bash
cd TubeMuse
```

```bash
npm install
```

```bash
npm run setup
```

`npm run setup` 会打印 **扩展 ID**（32 个 a–p 之间的小写字母）和 **授权回跳地址**（形如 `https://<扩展ID>.chromiumapp.org/`）。**把回跳地址复制下来**，下一步要用。

> ⚠️ `setup` 会在 `local/` 文件夹里生成你自己的扩展密钥，用来让扩展 ID 固定不变。这个文件夹只在你的电脑上，不会被提交到 Git。**不要删除 `local/manifest-key.txt`**，删了扩展 ID 会变，下一步建好的 OAuth 客户端就失效了。

<a id="google-cloud"></a>

#### 1.2 配置 Google Cloud（让扩展能只读访问你的 YouTube）

1. **建项目**：打开 <https://console.cloud.google.com/>，点顶部的项目选择器 → **新建项目**，名字随意（例如 `tubemuse`）→ 创建，并确认顶部已切换到这个项目。
2. **启用 YouTube API**：左上角菜单 → **API 和服务** → **库**，搜索 `YouTube Data API v3` → 点进去 → **启用**。
3. **配置同意屏幕**：左侧菜单 → **Google Auth Platform**（旧版界面叫"OAuth 同意屏幕"）→ **开始**，按向导填写：
   - **应用信息**：应用名称填 `TubeMuse`，用户支持邮箱选你自己。
   - **受众群体**：选 **外部（External）**。
   - **联系信息**：填你自己的邮箱 → 同意条款 → **创建**。
4. ⚠️ **把自己加为测试用户**（**最容易漏的一步**）：Google Auth Platform → **目标对象 / 受众群体（Audience）** → **测试用户** → **添加用户**，填你**打算用来连接 YouTube 的那个 Gmail**（就是你看 YouTube 用的账号）→ 保存。发布状态先保持 **测试中（Testing）**，不需要提交验证。
   > ⏳ Google 的规定：发布状态为"测试中"时，授权里的**刷新令牌 7 天后失效**，所以每 7 天要点一次"重新授权"。想去掉这个期限，见下面的 [可选：发布为正式版](#oauth-production)。
5. **添加权限范围**：Google Auth Platform → **数据访问（Data Access）** → **添加或移除范围**，搜索并勾选 `.../auth/youtube.readonly`（"查看您的 YouTube 账号"）→ 更新 → **保存**。
6. **创建客户端**：Google Auth Platform → **客户端（Clients）** → **创建客户端**：
   - 应用类型：**Web 应用（Web application）**
   - 名称：随意
   - **已获授权的 JavaScript 来源**：留空
   - **已获授权的重定向 URI** → **添加 URI**：粘贴第 1.1 步的授权回跳地址 `https://<扩展ID>.chromiumapp.org/`（整段复制，**结尾的 `/` 不能少**）
   - 点 **创建**。弹窗里有两样东西，**都复制下来**：
     - **客户端 ID**（形如 `123456-abcdef.apps.googleusercontent.com`）→ 下一步填进 `local/config.json`。
     - **客户端密钥（Client secret）**（多以 `GOCSPX-` 开头）→ 第 2 步在设置页里填。⚠️ Google 只在这个弹窗里完整显示一次，关掉后看不到了；没复制到也不要紧：在这个客户端的页面点 **Add secret（添加密钥）** 新建一个即可。
   - 以前按旧版说明建过"Chrome 扩展程序"类型的客户端？它在新版里用不了，按上面另建一个"Web 应用"类型的，并把新的 Client ID 换进下一步。
   - 已经有"Web 应用"客户端、只是当时没记 Client secret（旧版说明写的"不需要"）？打开这个客户端 → **Add secret** → 复制新密钥，不用新建客户端。

<a id="oauth-production"></a>
**可选：发布为正式版，去掉"刷新令牌 7 天失效"**

Google 只对"测试中"的应用施加 7 天期限。这是你一个人用的应用，可以直接发布、不提交验证：Google Auth Platform → **目标对象 / 受众群体（Audience）** → **发布应用（Publish app）** → 确认。之后：
- 连接时会看到"Google 尚未验证此应用"，点 **高级 → 转至 TubeMuse（不安全）** 继续（这是你自己的应用；未验证的应用最多 100 个用户，对你够用）。
- **发布前拿到的刷新令牌仍按 7 天失效**：发布后到设置页点一次 **重新授权**（或断开再连接），之后的刷新令牌就没有 7 天期限了（半年不用、或你在 Google 账号里移除授权时仍会失效）。

#### 1.3 填入 Client ID 并构建

用任意文本编辑器打开 `local/config.json`，把客户端 ID 填进去：

```json
{ "oauthClientId": "123456-abcdef.apps.googleusercontent.com" }
```

然后构建：

```bash
npm run build
```

终端最后几行应显示 `✔ 已构建 dist/`、扩展 ID、授权回跳地址，以及你的 OAuth Client ID。如果提示"还没有配置 OAuth Client ID"，说明上一步没保存成功。

4. 核对 TubeMuse 卡片上显示的 ID 与第 1.1 步一致。
5. 点工具栏的拼图图标 → 把 **TubeMuse** 固定到工具栏，以后点它就能打开侧边栏。

> 💡 装好后**不要移动或删除项目文件夹**，Chrome 每次都从这里加载。Chrome 有时会提示"停用开发者模式扩展程序"，选择保留即可。

<a id="firefox"></a>

#### 1.5（可选）在 Firefox 里使用

TubeMuse 也有 Firefox 版（Firefox **149 及以上**，在 **161.0b2 Beta** 上实测过）。功能、权限、网络出口和 Chrome 版一样，用的是同一个 Google Cloud 客户端。Firefox Beta / 正式版只能"临时载入"未签名的扩展，所以自己构建的 `.xpi` 每次重启 Firefox 后要重新载入一次（实测本机数据还在）；想**永久安装**，用 [Releases](https://github.com/Anna-SAP/TubeMuse/releases) 上 Mozilla 签过名的 `tubemuse-<版本>-firefox-signed.xpi`（见 [1.0](#download)，安装后从下面第 4 步接着做）。

1. **构建安装包**（Client ID 已写在 `local/config.json` 里的话会一起打进去；Firefox 版不需要 `npm run setup` 生成的密钥）：

   ```bash
   npm run build:firefox
   ```

   终端会打印 **安装包** `release/tubemuse-0.1.0-firefox.xpi`、**Firefox 扩展 ID** `tubemuse@tubemuse.local` 和 Firefox 的 **授权回跳地址**：

   ```
   https://bd64894190509c2a091730e87fc55c691c06b55d.extensions.allizom.org/
   ```

   这个地址由扩展 ID 算出，固定不变。

2. **把 Firefox 的回跳地址加到 Google Cloud**：Google Auth Platform → **客户端（Clients）** → 打开第 1.2 步建的那个"Web 应用"客户端 → **已获授权的重定向 URI** → **添加 URI**，粘贴上面这个地址（含结尾的 `/`）→ **保存**。Chrome 的那条（`…chromiumapp.org/`）留着不用删。保存后可能要等几分钟才生效。

3. **载入**：在 Firefox 地址栏打开 `about:debugging#/runtime/this-firefox` → **临时载入附加组件…（Load Temporary Add-on…）** → 选 `release/tubemuse-0.1.0-firefox.xpi`（也可以选 `dist-firefox/` 里的 `manifest.json`）。Firefox 会自动打开 TubeMuse 的设置页。

4. **首次配置**：和 [第 2 步](#setup) 一样。另外：如果设置页「2. YouTube 账号」里 **OAuth Client ID** 显示"未配置"（安装包构建时没带 Client ID，例如别人替你打的包），在下面的 **OAuth Client ID** 框里粘贴客户端 ID → 保存，再填 Client Secret、点"连接 YouTube"。

5. **打开侧边栏**：Firefox 把新扩展的按钮收在工具栏右侧的 **扩展（拼图）** 面板里：点拼图 → TubeMuse 旁的齿轮 → **固定到工具栏**。之后点工具栏上的 TubeMuse 图标开 / 关侧边栏。

6. **语音输入**（可选）：Firefox 的语音识别**只在本机**进行（Mozilla 的语音模型，没有云端服务）。设置页「4. 语音」会显示这个语言的本机模型状态，能下载时点 **下载** 即可（几百 MB，Firefox 可能先问你一次）；没有这个语言的模型时，语音输入用不了，直接打字。麦克风授权和 Chrome 一样先在授权页授权一次，Firefox 弹窗里勾上 **记住此决定**。

**Firefox 版与 Chrome 版的不同**

| | Chrome | Firefox |
|---|---|---|
| 安装方式 | 加载已解压的扩展程序（`dist`），一直保留 | Releases 上签过名的 `-signed.xpi` 从文件安装，一直保留；自己构建的 `.xpi` 只能临时载入，重启 Firefox 后要重新载入 |
| 授权回跳地址 | `https://<扩展ID>.chromiumapp.org/` | `https://bd64894190509c2a091730e87fc55c691c06b55d.extensions.allizom.org/` |
| 侧边栏 | 点工具栏图标打开（Chrome 侧边栏） | 点工具栏图标开 / 关（Firefox 侧边栏） |
| 语音输入、自动字幕的"浏览器识别" | 有本地语音包时在本机识别，否则发往 Google 的云端服务（界面明示） | 只在本机识别；这个语言没有本机模型时用不了（界面写明原因，自动字幕可改用 OpenAI 转写） |
| 自动字幕第二行的"本地翻译" | Chrome 138+ 的本地翻译 | Firefox 没有给扩展用的本地翻译接口：改用大模型翻译 |
| 片段录制的文件格式 | MP4（H.264 + AAC） | WebM（VP8 + Opus） |
| 改快捷键 | `chrome://extensions/shortcuts` | `about:addons` → 齿轮 → 管理扩展快捷键 |
| 网站权限 | 安装时就给了 | 安装时默认给，但可以在 `about:addons` → TubeMuse →「权限」里收回；收回后侧边栏和设置页顶部会写明缺哪些，点"授权访问这些网站"即可恢复 |

<a id="setup"></a>

### 2. 首次配置（约 5 分钟）

第一次加载后，Chrome 会自动打开 TubeMuse 的**设置页**（以后也可以点侧边栏右上角的 ⚙ 打开）。

**① 大模型（必填）** —— 设置页 **1. 大模型（LLM）**

1. **当前使用**：选 Anthropic 或 OpenAI。
2. 在对应的 **API Key** 框里粘贴 Key → **保存**。保存后输入框只显示"已保存（出于安全不回显）"，这是正常的。
   - Anthropic 用户：在 [Claude Console → API keys](https://platform.claude.com/settings/keys) 点 **Create key** 时，建议把 Key **限定到某个工作区**（workspace），这样下面的"工作区 ID"可以留空。
   - 如果你的 Key 没有限定工作区（测试时报"Key 没有绑定工作区"），到 [Workspaces](https://platform.claude.com/settings/workspaces) 页的 **ID** 列复制工作区 ID（`wrkspc_` 开头），填到 **Anthropic 工作区 ID（可选）** → **保存**。
3. 模型名可以先保持默认（Anthropic：`claude-opus-5-5`；OpenAI：`gpt-6.1-sol`）。想省钱可以换成更便宜的模型，例如 `claude-sonnet-5-5`。
4. （可选）点 **测试连接**，看到"连接正常"即可。这会产生一次极小的真实调用。

**② 连接 YouTube（必填）** —— 设置页 **2. YouTube 账号（只读授权）**

1. 确认"OAuth Client ID"一栏显示了你的客户端 ID（不是"未配置"），"授权回跳地址"与你填进 Google Cloud 的一致。
2. 在 **OAuth Client Secret** 一栏粘贴第 1.2 步复制的客户端密钥 → **保存**（只存在本机，出于安全不回显）。
3. 点 **连接 YouTube**，会弹出 Google 登录 / 授权窗口：
   - 登录（或选择）你加进测试用户的那个 Google 账号。
   - 出现"Google 尚未验证此应用"时，点 **继续**（这是你自己的测试应用）。
   - 授权内容应该只有"查看您的 YouTube 账号"，点允许。每次连接都会显示这一页（这样 Google 才会发刷新令牌）。
4. 状态变为 **已连接，自动续期已开启** 即完成；下面一行写着刷新令牌是什么时候拿到的、什么时候会被 Google 作废。

> 💡 访问令牌约 **1 小时**有效。连接时 TubeMuse 还会拿到一个**刷新令牌**：访问令牌过期后，后台用它向 Google 换新的——**不弹窗、不依赖这个浏览器里网页版 Google 的登录状态**，扩展重新加载、浏览器重启后照样有效。只有刷新令牌本身失效时（应用处于"测试中"满 7 天、你在 Google 账号里移除了 TubeMuse、改了密码）才需要你点一次 **重新授权**；侧边栏顶部会写明原因。网络断了只会让这一次请求失败、提示"授权本身没有失效"，不会要你重新授权。授权窗口由扩展后台打开、令牌由后台保存：窗口开着时侧边栏或设置页被关掉也没关系。
>
> 从旧版本升级上来的：旧授权没有刷新令牌，侧边栏顶部会提示"YouTube 授权是旧版"。填好 Client Secret、点一次 **重新授权** 即可。

**③ 近期学习目标（推荐）** —— 设置页 **7. 每日总结与每周自省** → **近期学习目标**

例如"这个月把大模型的基本原理补上"。每晚的总结会写"今天的观看和这个目标有什么关系"。

**④ 语音授权（想用语音再做）** —— 设置页 **4. 语音**

Chrome 的侧边栏没法直接弹出麦克风授权框，所以要单独授权一次：点 **打开麦克风授权页** → 点 **授权麦克风** → 浏览器弹窗里选 **允许** → 看到"授权成功"后关掉这个页面。只需做一次。

**⑤ X 热点（可选，需要付费）** —— 设置页 **9. X 热点**

1. 打开 <https://developer.x.com>，进入开发者后台（Developer Console），创建一个项目和应用。
2. 在后台购买少量额度（credits），并**设置花费上限**（Spending limit），作为双重保险。
3. 在应用的 **Keys and tokens** 里生成 **Bearer Token**，复制下来。
4. 在 **X Bearer Token（App-only）** 框里粘贴 → **保存**。默认每日预算 $0.50，可以改。打开"发现"页不花钱，只有点 **刷新热点** 才读 X（一次最多 $0.20）。

**⑥ 自动字幕（默认关闭，需要时手动开启）** —— 设置页 **12. 自动字幕**

字幕默认关闭：看视频时在侧边栏 **字幕** 页点 **为这个视频生成字幕**，或按 `Alt+Shift+S`，只对这一个视频生效。想让没有原生字幕的视频自动开始，勾选 **播放器显示"字幕不可用"时自动开始**。

1. **转写方式**默认是 **浏览器识别**：免费，把视频的声音交给浏览器自带的语音识别，边说边出字。**只有 Google Chrome 能用**（Comet 等浏览器连不上这项服务，那就改用 OpenAI 转写）。
2. 默认由 Chrome 的云端服务识别（声音由 Chrome 发往 Google）。想让声音不离开电脑：点 **下载「中文（简体字）」本地语音包**，装好后自动改在本机识别（页面上会显示"已安装"）。
3. **识别语言**默认"自动"：按视频的语言（YouTube 数据，每个新视频查一次，1 unit），中文按简体字识别。判断错了在侧边栏 **字幕** 页给这个视频换一种。
4. **翻译方式**默认是 **Chrome 本地翻译**：免费，字幕文字不离开电脑。第一次用之前点 **下载本地翻译语言包**（Chrome 要求你点一下，语言包由 Chrome 下载）。没下载时第二行不显示，并写明原因，不会悄悄改用收费的大模型。想要更好的译文可以改选 **大模型翻译**：默认用 `claude-haiku-5-5`（1. 里选 OpenAI 时是 `gpt-6-luna`），每句调用一次，一小时约 $0.08。
5. 想改用 OpenAI 转写：选 **OpenAI 转写**，在 **1. 大模型** 填 OpenAI Key，并确认 [platform.openai.com → Settings → Billing](https://platform.openai.com/settings/organization/billing) 里有余额。
6. **刷新已经打开的 YouTube 标签页**（扩展安装或更新后都要刷新，字幕脚本才会生效）。

**⑦ 多语字幕（免费，默认关闭，不用配置）** —— 设置页 **13. 多语字幕**

看有 YouTube 字幕的视频时，在侧边栏 **字幕** 页点 **显示多语字幕**（或按 `Alt+Shift+C`），播放器底部就同时叠出几种语言的字幕，一种语言一行。想改默认语言再来这一节：

1. **显示的语言**默认从上到下是 **视频原声语言 → English → 简体中文**；用 ↑ ↓ 调顺序、✕ 去掉、**添加一种语言**（最多 4 种）。"视频原声语言"按 YouTube 自动生成字幕的语言判断，没有时查一次 YouTube 数据（1 unit）。
2. 视频没有你选的某种语言时，默认用 YouTube 自带的自动翻译补上（这一行标"机翻"，不花钱）；不想要就取消 **用 YouTube 自带的自动翻译补上**。
3. 想打开有字幕的视频就自动显示，勾选 **有 YouTube 字幕的视频自动显示**（默认不勾；2026-11-06 起旧版勾过的也作废，要重新勾选才生效）。
4. 同样要**刷新已经打开的 YouTube 标签页**。

<a id="tour"></a>

### 3. 跟着做一遍：第一次体验（约 15 分钟）

点工具栏的 TubeMuse 图标打开侧边栏。顶部的标签页：**找片 · 发现 · 豆瓣 · 字幕 · 记录 · 画像 · 改进记录**。标签页右端的 **图钉** 可以把这一行固定在配额条下方：往下翻长结果时它一直在，随时能切换；再点一次恢复随页面滚动。这项选择保存在本机设置里，重新打开侧边栏仍然有效。最上面是配额条：`search` 是今天用了几次 YouTube 搜索，`units` 是其他接口的用量；`AI $` 是今天大模型花了多少钱和每日上限；填了 X Token 后还会多一条 `X $`，显示今天在 X 上花了多少钱；开启自动字幕时还有一条 `字幕 $`，显示今天字幕花了多少钱。

**第 1 步　建立你的画像**

1. 点 **画像** → **同步订阅与喜欢的视频**。按钮旁会显示预计消耗多少 units（一般十几个），完成后显示订阅数和"喜欢的视频"数。
2. 点 **生成兴趣簇**（调用一次大模型），几秒后出现 4–10 个兴趣簇。
3. 逐个看一下兴趣簇，按需调整：
   - **倾向**：选 学习 / 娱乐 / 说不清。这会影响"记录"页对学习和娱乐的判定，以及导师提醒推荐什么。
   - **权重**：越高，这类视频在找片结果里越靠前。
   - 名称、关键词、所含频道都可以改。你改过的簇会标"已锁定"，以后点"重新生成"时会保留。

**第 2 步　第一次找片**

1. 点 **找片**，在输入框里写：`帮我找两天内最新的 AI 技术科普视频`，按回车或点 **找片**。
2. 先出现 **我的理解**，每一行是一个要求：
   - 「两天内」→ 发布时间：2 天内 → **已落实**
   - 「最新」→ 排序偏好：越新越好 → **近似落实**
   - 「科普」→ 形式：科普讲解 → **近似落实**

   状态的含义：**已落实**＝一定满足；**近似落实**＝尽量满足；**部分落实**＝有一部分做不到；**仅作参考**＝只是轻微加分；**无法满足**＝做不到，会写明原因。你说的每个要求都会出现在这里，不会被悄悄丢掉。
3. 下面是结果卡片：缩略图、标题、频道（已订阅的会标出）、时长、发布时间、播放量，带 ✓ 的小标签表示满足了哪些要求，还有 **为什么推给你**。
4. 点任意标题，视频会在**当前标签页**打开。

**第 3 步　打分，看它怎么变**

1. 找一条你不喜欢的，点 **3**。卡片上会问"主要是哪里不对？"，选 **意思对，但这条找错/排错了**。
2. 卡片上立刻出现 **因为这次打分，系统改了：**，列出具体调整，例如"频道偏好 0.00 → -0.22，之后它的视频会更靠后"。不满意可以点 **撤销这次调整**。
3. 找一条你喜欢的，点 **10**，同样会显示改了什么。
4. 结果上方出现"排序参数已根据你的评分更新"，点 **按新偏好重排当前结果**（不消耗配额），卡片标题旁会出现 ↑↓ 名次变化。
5. 打开 **改进记录** 标签页，能看到当前各因子权重与默认值的对比、频道偏好，以及每一次调整的明细，每条都能撤销。

> 💡 如果低分的原因是它**没听懂你的意思**，选 **理解错了我的意思** → 选出哪一项理解错了 → 写一句"我其实想要……" → **记下这条纠正**。它不会改排序，而是把这条纠正带进以后的理解里。可以马上点 **按纠正重新理解并搜索** 验证。

**第 4 步　试一句要求很多的口令，并修改它**

1. 输入：`英文、一小时以上、近一周、带字幕、不要 Shorts 的 AI 安全访谈`。
2. "我的理解"里会列出约 7 行：语言、时长、时效、字幕、排除 Shorts、主题、形式，每行写明怎么落实。回显下方会显示 **候选 N 条 → 某条件淘汰 M → … → 剩 K 条**。
3. 改一改：点"时长"那行的 ✎，把 60 改成 20 → **完成** → **按修改重搜**。因为只改了过滤条件，会显示 **缓存**，不消耗配额。
4. 也可以用 **+ 添加约束…** 加一个要求，或点 × 删掉一个，或直接改下面的检索词。

**第 5 步　试一下语音（需完成上面的语音授权）**

1. 在 **找片** 页点 **🎤 说**，说一句中文，例如"找几个讲解量子计算的入门视频"。
2. 说完后文字只会**填进输入框**，不会自动搜索。确认无误再点 **找片**。
3. 麦克风旁会写明识别方式：**本地识别**（音频不离开电脑）或 **云端识别（音频发往 Google）**。旁边的下拉框可以在中文和 English 之间切换。

**第 6 步　看视频，然后看记录**

1. 先**刷新已经打开的 YouTube 标签页**（扩展安装或更新之后都要刷新一次，追踪才会生效）。
2. 在 YouTube 上：完整看完一个短视频；打开另一个，两三秒就关掉；第三个看一半左右（可以开 2 倍速）。
3. 回到侧边栏 → **记录**：三条分别标为 **看完 / 瞥一眼 / 部分观看**。规则是：完成率 ≥ 85% 算看完；完成率 < 15% 或有效观看 < 30 秒算瞥一眼。暂停、广告、拖动进度条都不计入。在后台标签页播放的会标 **后台收听**。
4. 每条还标了 **学习 / 娱乐 / 其他**。点 **判定依据 / 纠正** 能看到为什么这么判，可以 **只改这条**，或者 **这个频道都算……**。
5. 点 **现在生成今天的总结（预览）**，展开后能看到 **今日学了什么 / 值得回看 / 只是路过 / 与近期目标的关联**。真正的总结会在每天 23:00 自动生成。

**第 7 步　发现**

1. 点 **发现**：
   - **X 热点**（填了 Token 才有）：点 **刷新热点** 后出现 5–8 条，每条都有 **原文 ↗** 链接。点 **用这句找片：「…」** 会自动跳到找片并开始搜索。
   - **本周新博主**：点 **现在发现**，最多推荐 5 个你还没订阅、最近活跃的频道，每个附推荐理由和最近 3 个视频标题。只有 **打开频道** 和 **不感兴趣** 两个按钮，不提供订阅。
2. 标题旁会显示本周已用的 search 次数（每周最多 8 次），以及今天的 X 花费。

**第 8 步　自动字幕（用 Google Chrome）**

1. 在 YouTube 打开一个**没有字幕**的视频（播放器的字幕按钮提示"字幕不可用"），开始播放。字幕默认关闭，这时什么都不会出现；侧边栏 **字幕** 页显示"未开启（字幕默认关闭）"。
2. 在侧边栏 **字幕** 页点 **为这个视频生成字幕**（或按 `Alt+Shift+S`）。播放器左上角先出现一行小字"TubeMuse 字幕：正在听…（中文（简体字） · Chrome 云端识别（声音发往 Google））"；对方一开口，画面下方就开始逐字出现原文，每满一行（或停顿时）定稿，下面一行出现译文（中文视频译成英文，其他语言译成简体中文）。
3. 打开侧边栏 **字幕** 页：能看到当前视频、"原生字幕：没有"、转写方式与声音去向、识别语言（可以换）、已生成几句，以及今天花了多少钱。
4. 把进度条拖回前面一点：字幕和说话**精确对齐**，而且不再花钱（已经识别过的部分直接用本机保存的字幕）。
5. 点 **关闭这个视频的字幕**（或按 `Alt+Shift+S`），字幕立刻消失；再点一次重新打开。
6. 换一个视频：字幕又回到关闭，需要时再点一次。有原生字幕的视频也能这样手动生成一份。

**第 9 步　多语字幕**

1. 打开一个有多种字幕的视频（例如 TED 演讲 `https://www.youtube.com/watch?v=arj7oStGLkU`，或一支带中 / 英 / 韩字幕的 MV），开始播放。
2. 在侧边栏 **字幕** 页最上面的 **多语字幕** 里点 **显示多语字幕**（或按 `Alt+Shift+C`）。一两秒后，播放器底部叠出几行字幕：第一行原声语言（白色），下面是 English（浅黄）、简体中文（浅蓝）；YouTube 原生字幕若开着，会暂时关掉，免得出现两层。
3. 侧边栏列出这个视频所有的 YouTube 字幕：正在显示的打了勾，并写明"原生字幕 / YouTube 自动生成 / YouTube 机翻"和读到几句。勾选另一种（比如日语）就立刻加一行；只对这个视频生效。已勾选的语言从上到下就是播放器里的显示顺序，点右边的 ↑ ↓ 调整，字幕行立刻跟着换位；想让所有视频都这样，点 **把这组语言和顺序设为默认**。
4. 拖动进度条、全屏、切剧场模式：每种语言都按自己的时间轴对准画面，字号跟着播放器变大。
5. 点 **关闭多语字幕**（或再按 `Alt+Shift+C`）：字幕层消失，原生字幕恢复成你原来的样子。

🎉 到这里，所有功能你都用过一遍了。

> 💡 （可选）**导入 YouTube 观看历史**：YouTube 官方接口不提供观看历史。可以在 [takeout.google.com](https://takeout.google.com) 只导出"YouTube 和 YouTube Music → 历史记录"、格式选 **JSON**，然后在 **画像** 页底部选择 `watch-history.json`。文件只在本机解析。

| 想做什么 | 怎么做 |
|---|---|
| 看笔记的发布时间 | 博主主页、首页、搜索结果的每张笔记卡片上，**作者名与点赞数之间**直接显示，如 `2026/10/28 07:04`（你电脑的时区，24 小时制）；笔记详情的日期旁显示"发布于 …" |

### 小宇宙

在 Chrome 里正常打开小宇宙网页版的单集页（`https://www.xiaoyuzhoufm.com/episode/…`），点播放，再打开侧边栏的 **小宇宙** 页。上面是这一集（封面、标题、节目、时长）和 **☆ 收藏这一集 / ☆ 收藏节目**，下面分四块：

| 想做什么 | 怎么做 |
|---|---|
| 看字幕 | **字幕** → **开始字幕**（或按 `Alt+Shift+S`）。几秒后页面底部播放器上方出现字幕：第一行中文、第二行英文。中文节目：中文是转写后经大模型校对的（改错字和同音字、补标点、按节目简介统一人名和术语），英文是译文；英文节目反过来。刚转写出来、还没校对的那一句先显示原文，几秒后换成校对好的 |
| 只看一种语言 / 收起 | **双语 / 中文 / English / 不显示** |
| 跳到某一句 | 侧边栏下面的字幕列表里点那一句（当前在放的那句高亮） |
| 下载字幕 | 先 **生成整集字幕（用于下载）**：先给出预计花费和今天剩下的字幕额度，**确认生成** 后从头转写整集（不用一直听着，标签页开着就行），进度条走完显示"整集字幕已生成"；再在 **下载字幕** 里选格式（SRT 中英双语 / 中文 / English、WebVTT 中英双语、纯文本、Markdown 文稿）点 **下载**。没生成完也能下载，只含已生成的部分，文件里注明覆盖到哪里 |
| 做一张分享快照 | **片段快照**：默认选好当前这句（不够 20 秒连上后面几句），**开始 / 结束** 可以改、可以 **取当前**；页面进度条上同时标出起止。下面是卡片预览（单集封面、标题、节目名、"TubeMuse × 小宇宙"、这一段的中文字幕引文和英文、真实波形里高亮这一段、`04:52 – 05:18 (26s)`）；卡片上的文字可以改。**分享这段快照**（交给系统的分享面板；浏览器不支持时把图片放进剪贴板）、**导出图片**（PNG 存进下载文件夹，同时放进剪贴板）、**复制链接**（单集链接 + 片段起止）、**导出音频片段**（这一段的 WAV）、**▶ 试听**（页面上从起点放到终点自动暂停）。做过的在 **我的快照** 里 |
| 收藏 | 点上面的 **☆ 收藏这一集 / ☆ 收藏节目**；**收藏** 里按单集 / 节目、标签、关键词筛选，加减标签、改名 / 删除标签、移出。只存在本机，不会在小宇宙上订阅或收藏 |
| 看听过什么 | **收听记录**：按日期列出在小宇宙网页版上听过的单集，"听完 / 听了一部分 / 只听了一点"、听了多久、听到哪里、听过多少内容（拖动跳过的不算）。可以删单条或清空 |

要知道的：

- **字幕从哪来**：小宇宙页面上的播放器是跨站的，浏览器不让扩展从它取声音；所以字幕开启后，TubeMuse 只读这一集在小宇宙 CDN（`media.xyzcdn.net`）上的公开音频文件，一次读一段（约 30 秒），在本机解码、按停顿切句，再一句一句交给 OpenAI 转写。边听边转写时最多提前 2 分钟（设置页「18. 小宇宙」可改）；暂停时转写到那里就停，不会一下子把整集都花掉。转写过的部分存在本机，回听、拖回去、下载都不再花钱。付费 / 会员节目的音频不在公开 CDN 上，读不了，侧边栏会说明。
- **质量**：转写用 OpenAI `gpt-transcribe`（和"12. 自动字幕"同一个模型），一句最长 12 秒、带着节目名、标题和前文，再由大模型（"12. 自动字幕"里的字幕翻译模型，默认 `claude-haiku-5-5`）对照节目简介校对。没有 OpenAI Key 时可以一键 **改用浏览器识别（免费）**：浏览器只能按 1 倍速边放边认，质量接近系统自带的实时字幕，靠大模型补标点、改错字。
- **可变码率的 mp3**（部分从 RSS 同步来的节目）：浏览器跳转时按文件头里的目录粗略定位，报告的时间和实际在放的声音能差几秒到一分钟。TubeMuse 第一次为这样的一集出字幕时，先把音频文件从头读一遍、只记下每一帧的位置（侧边栏显示"正在建立时间索引 x%"，几十 MB，只读帧头、不保存音频），之后按浏览器的定位规则换算，字幕对得上实际在放的声音。
- **花费**：一小时的节目约 $0.30（转写约 $0.27 + 校对 / 翻译），记在顶部的 **字幕 $** 里，和 YouTube 自动字幕共用每日预算（默认 $1）；到上限立即停止并说明。
- **快捷键** `Alt+Shift+S`：在小宇宙单集页上开关这一集的字幕（在 YouTube 上照旧开关自动字幕）。

### eMails

在 Chrome 里正常打开 Gmail（`mail.google.com`），点开一封文章汇总邮件，再打开侧边栏 **eMails** 页。不需要额外配置，用的是设置页"1. 大模型"里的 Key；打分和总体结论默认用省钱模型，按钮下面写着这次大约花多少。

| 想做什么 | 怎么做 |
|---|---|
| 看邮件里有哪些文章 | 点开邮件，**eMails** 页自动列出：标题（被邮件截断的会还原成完整标题）、作者、刊物、阅读时长、掌声、回应数、摘要。换一封邮件，列表跟着换 |
| 评估价值 | 点 **评估这 N 篇**：每篇得到 0–10 分和一句理由，按分数从高到低排。这一步才会发给大模型，发什么写在按钮下面 |
| 看这封整体怎么样 | 评完后筛选按钮上方出现 **总体结论**：一句话（"这 15 篇里没有值得精读的"）、分数分布（平均、最高，离精读线还差几分）、大模型写的整体质量概述。**一篇值得精读的都没有时，多一段"为什么一篇都没有"** |
| 过滤低质内容 | 用上方的 **值得精读（≥7）/ 一般（4–6）/ 建议跳过（≤3）** 筛选；0 分是毫无阅读价值的低质内容（Slop），10 分是极具深度、值得精读的文章 |
| 读一篇 | 点标题，在新标签页打开（链接已去掉跟踪参数，不把正在看的邮件换掉） |
| 收藏 | 点文章下面的 **☆ 收藏**（分数和理由一起存下），就地加标签 |
| 看全部收藏 | **eMails** 页顶部切到 **收藏**：按标签、关键词（标题、作者、刊物、标签）筛选；**管理标签** 可改名、删除；**移出收藏** 可以 **撤销** |
| 重新评估 | 全部评过后按钮变成 **重新评估**（重新花钱），比如换了模型之后。总体结论跟着重写 |
| 只要总体结论 | 文章都评过、还没有结论时（比如文章是之前评的），**总体结论** 里有 **生成总体结论**：不重新打分，只花写结论这一次的钱 |

- **分数和结论都只是预判**：大模型只看到标题、摘要、作者和互动数，**没有读正文**（读正文要访问文章网站，不在网络出口白名单里）。高分文章值得点开，低分文章也可能看走眼。
- **评过的不再花钱**：评分按文章缓存，同一篇隔天又出现在别的汇总里，会直接显示分数，按钮变成"评估剩下的 N 篇"。一封十几篇的汇总，用默认模型约 $0.03–0.06（其中总体结论约 $0.01），每次评完会显示大约花了多少。
- **总体结论跟着分数走**：一句话和分数分布在本机算，不花钱，大模型出错时也在。大模型写的那段按"这封邮件的文章和各自的分数"存：关掉侧边栏再回来还在；分数变了（比如重新评估过）就不再显示，可以重新生成。还有文章没评时不下结论；大模型漏评了几篇时，结论只说评过的那些。
- **普通邮件不会被发出去**：认不出文章列表时写"这封邮件不像文章汇总"，没有"评估"按钮。
- **其他汇总邮件**：按"链接里的标题 → 链接里的粗体 → 够长的文字链接"三档识别，Medium 之外的版式可能认得不全，以你看到的列表为准。

浏览器识别边说边出字，时间按出字时刻估算（误差约 1 秒）；OpenAI 转写要等一句说完、上传识别后才出现，所以会晚几秒（每段最长 7 秒）。这是"不下载视频"的代价：只能边播边听。字幕按视频时间存在本机，拖回去或下次再看时就是对齐的，也不会重复花钱。

### 配音

| 开 / 关 | 侧边栏顶部的 **开启配音**，或 **配音** 页的 **开启配音 / 关闭配音**（开着时图标上的 **中** 变绿）。只对这个视频、这个标签页；刷新页面后回到"只提示" |
| 中文跟着视频走 | 不用管：播放、暂停、拖动进度、改倍速时中文跟着；视频缓冲、跳转时中文等它；广告期间中文暂停、原声恢复。关掉侧边栏也继续 |
| 对齐第一句 | **配音** 页的 **对齐**：**+** 让中文推后（中文比原视频晚出来，往回退），**−** 让中文提前（往前跳）；**±0.1 / ±1 秒 / ±10 秒 / ±1 分** 微调，或直接输入秒数；也可以拖 **中文位置**，直接选"此刻放中文的哪里"。拖动时立即生效，松手后按视频存下，下次打开直接用。**位置** 一行显示此刻视频与中文各放到哪里 |
| 越往后越对不上（中文短了很多） | 中文是另外录的，语速、停顿不一样，还可能删掉了一些段落，一个偏移管不了全程。在对不上的地方点 **在这里加对齐点**（加完听到的不变），再用上面的按钮或 **中文位置** 把这一段调到中英说的是同一句——只改这一个对齐点之后的那一段，前面的不受影响。对齐点之间中文按正常速度放：**中文先说完就停下等画面**（这时听到的是原声），**说得慢就在下一个对齐点跳过去**（跳过中文没说完的那一点）。拖进度条到哪里都按所在那一段换算。**对齐** 一栏写着现在在哪一段 |
| 管理对齐点 | **对齐** 下面的列表：开头的偏移和每个对齐点（视频时间 ↔ 中文时间、这一段的偏移），现在所在的那一段高亮；**删除** 后可以 **撤销**。中文位置比前一个还靠前的对齐点会标出来（前一段的中文会被整段跳过）。离已有的对齐点不到 1 秒再加，等于改那一个；最多 200 个 |
| 看对齐状态（对齐图） | **对齐** 一栏最上面的 **对齐图**：粗体一行写此刻（"视频 1:51 ↔ 中文 1:26，中文比画面晚 25 秒"，或"中文停下等画面"），下一行写全片（照现在的对齐，中文在视频哪里放完、后面还有多少只有原声、全片差多少已经抵掉多少）。**全片**：上英文、下中文，按各自的时间、同一个比例画，中文短就短一截，色带连着同时听到的两处，越往后斜得越厉害。**附近**（30 秒 / 2 分 / 10 分）：播放头前后放大，下面的中文按这一段的偏移错开画，竖着对上的就是同时听到的；色带上写着每一段差多少，灰色斜纹 = 只有原声（中文还没开始 / 停下等画面），橙色斜纹 = 中文已放完，红色斜纹 = 被跳过的中文，圆圈是对齐点（编号和列表一样）。鼠标指着哪里就说那里听到的是什么。**左右拖下面的中文** = 调这一段的偏移（往右 = 中文推后），拖动时立即生效，松手后存下。图随播放、加 / 删对齐点、调偏移实时更新 |
| 原声的音量 | 配音开着时原声是你的音量的 80%（**配音** 页 **原声** 一行写着"你的音量 → 现在"），中文保持正常音量、不跟 YouTube 的音量与静音走。开着时你在 YouTube 上调音量，按新的音量再降 20%；关闭、换视频、离开页面时原声恢复 |
| 换一个文件 | **配音** 页 **换一个文件…**（偏移和对齐点保留；新文件不一样的话在对齐点列表里删掉重设） |
| 移除 | **配音** 页 **移除…** → **确认移除**：音频从浏览器里删掉，你电脑上原来的文件不受影响。**已关联的视频** 列表里管理全部（点标题打开那个视频） |
| 录一段带中文配音的片段 | 开着配音时到 **片段** 页录：**声音** 一行写着"录下的片段是双语混音"，录下的就是你听到的——原声降 20% 加中文配音（比例固定，不跟 YouTube 的音量条走）。录制中途关掉配音，后面那部分就只有原声。录好的片段标"双语混音" |
| 不想看到提示 | 设置页 **19. 中文配音** 取消 **打开有中文配音的视频时提示**；整个功能也可以在那里关掉 |

按 1 倍速实时录：截一段 5 分钟的片段就要播 5 分钟，倍速播放时按当前倍速录。小红书的视频放到最后会停在最后一帧（不报"播完"），TubeMuse 按"停在结尾超过 1 秒"算播完、自动结束这一段。付费电影等受版权保护（DRM）的视频浏览器不允许录。**录下的片段和截图仅供个人学习，请勿传播**（YouTube 的服务条款不允许未经许可下载或转发它的内容；小红书、Instagram、抖音的内容同样属于作者；酷播上的影视剧属于各自的版权方）。

### 问 muse

看视频时想问点什么，又不想自己整理"我在看哪个视频的哪一段"：点侧边栏顶部的 **问 muse**——顶部那一行右边、设置齿轮旁边的毛绒小人，是一个图片按钮，鼠标停上去会显示它是做什么的；面板展开时它带一圈红框。下文说"点 **问 muse**"都是指点它。TubeMuse 把这些整理成一段文字（咨询包），你复制后粘贴到 Muse 聊天（<https://muse.ai/>）里提问。TubeMuse 只生成这段文字：不会替你发送，不调大模型，不花钱。

| 想做什么 | 怎么做 |
|---|---|
| 问正在看的这一段 | 看到想问的地方 → 点顶部的 **问 muse**。这一刻的播放位置就记下来了（"冻结"：只是记下，**视频不会暂停**）→ 在 **我的问题** 里写下问题 → **生成** → **复制** → **打开 muse.ai** → 在 Muse 的输入框里粘贴、发送 |
| 换一个位置再问 | 再点一次 **问 muse**：重新冻结成现在的位置（写好的问题还在） |
| 改了问题 | 点 **生成** 更新下面那段文字。直接点 **复制** 也行：它总是先按现在的问题更新再复制 |
| 带上字幕当上下文（YouTube） | 不用做什么：点 **问 muse** 时会自己取这个视频自带的字幕（人工字幕或 YouTube 自动生成的字幕），只放位置前后 30 秒；一般要等一两秒。原来没开字幕的话，播放器里的字幕会闪一下。视频本身没有 YouTube 字幕时写「无字幕」，这时可以先在 **字幕** 页打开 **自动字幕**（语音识别），等字幕出来再点一次 |
| 不想让它动播放器 | 面板里取消勾选 **YouTube：点「问 muse」时自动取视频自带的字幕**。关掉后只用已经读到的字幕（多语字幕读到的、自动字幕转写的） |
| 收起面板 | 面板右上角的 **×**。咨询包不存本机，关掉侧边栏就没了 |

咨询包长这样（所有平台同一组字段；没有的项写「无」，播放位置读不到写「未知」，不编造）：

```
平台：YouTube
页面链接：https://www.youtube.com/watch?v=xxxxxxxxxxx&t=123s
标题：How transformers work
作者：Explain Lab
播放位置：02:03 / 18:20
章节：上一章 [00:00] Intro；当前 [01:30] Attention；下一章 [05:00] Training
简介：
A visual explainer of attention.
上下文（当前位置前后 30 秒的字幕 · YouTube 字幕（English））：
[01:35] Attention lets the model look back.
[02:04] Each token asks a question.
我的问题：这里的"注意力"到底在算什么？

视频里的说法必须引用位置或原文；通用概念问题可用通用知识回答，但必须标明「这是通用知识，不是视频原话」。
```

各平台填什么：

| 平台 | 在哪个页面点 | 标题 | 作者 | 章节、简介 | 上下文 |
|---|---|---|---|---|---|
| YouTube | 播放页或 Shorts | 视频标题 | 频道名 | 来自 YouTube 官方接口（和作者一起查，不读页面；本机没记着这个视频时查一次，1 unit）。章节从简介里认，只放当前位置所在的那一章和前后各一章；简介超过 1500 字只放开头并注明 | 位置前后 30 秒的字幕：点的时候自己取视频自带的（已经读到的直接用），取不到再用自动字幕的转写；都没有时写「无字幕」 |
| 小红书 | 笔记详情（浮层或单独的页面） | 笔记标题 | 作者名 | 无 | 这篇笔记的正文 |
| X | 帖子页，或首页信息流（`x.com/home`）里开着声音在播的那个视频 | 无（帖子没有标题） | 作者名 | 无 | 这条帖子的正文 |
| Instagram | 首页信息流里开着声音在播的那个视频 | 无 | 用户名 | 无 | 这条帖子露出来的正文 |
| 抖音 | 精选页、搜索结果页里点开的视频 | 无 | 昵称 | 无 | 这条视频的描述 |
| B 站 | 有主播放器的页面（视频、番剧、课程、播放列表、活动页） | 页面标题里的标题（番剧是片名，换过集以后带集数） | 无（UP 主不读） | 无 | 只有标题 |
| 酷播 | 播放页 | 片名 | 无（不读页面上的其他内容） | 无 | 只有标题（写"只有上面的标题"，不把标题再抄一遍） |

- 上下文只取一种。YouTube：位置前后 30 秒的字幕 / 转写，没有就是「无字幕」。别的平台：这条帖子 / 笔记的正文或描述，没有就只有标题。超过 2000 字会截断，并在咨询包里注明（字幕保留离冻结位置最近的那几句，正文保留开头）。
- 最后一句是给 Muse 的指令：视频里的说法必须引用位置或原文；通用概念问题可以用通用知识回答，但要标明"这是通用知识，不是视频原话"。
- 只有 YouTube 的链接带时间（`&t=秒数s`）。Shorts 的链接是它自己的 `/shorts/…` 网址，不带时间（Shorts 的网址不认时间参数）。别的平台没有按时间打开的地址，只给页面链接和播放位置。
- 小红书的链接不带 `xsec_token`（它是令牌，不进咨询包），所以从外面打开这个链接时小红书可能要求登录。
- 咨询包里不会有你的 API Key 或令牌；页面文字、字幕或你的问题里如果有看起来像 Key / 令牌的内容，会换成"[已隐藏]"，面板里会告诉你。
- 广告期间（YouTube，以及酷播认得出的片头广告）、没有视频的笔记和帖子：播放位置写「未知」，面板里说明原因。Shorts 的播放位置和字幕 2026-11-11 起照常带上。
- 当前标签页认不出正在看的视频时（不是视频页、信息流里没有开着声音在播的视频、扩展更新前打开的页面）不生成咨询包，面板里说明怎么办。

## 🔒 隐私与数据

- **只存本机**：所有数据都在这台电脑的浏览器里（Chrome / Firefox 的扩展本地存储 `storage.local`），没有服务器，也没有账号体系。
- **只连官方接口**：网络出口由内容安全策略（CSP）强制限制为下面这些地址（设置页底部"网络出口"也有列表）：
  - `https://www.googleapis.com`（YouTube Data API v3，只读）
  - `https://oauth2.googleapis.com`（Google 令牌端点：连接时用授权码换令牌、之后用刷新令牌续期，Client Secret 与刷新令牌只发往这里、只放在请求体里；断开连接时吊销授权）
  - `https://api.anthropic.com` 或 `https://api.openai.com`（你选定的大模型；自动字幕的语音转写也发往 `api.openai.com`）
  - `https://api.x.com`（X 官方 API v2，只读；填了 Token 才会连接，只发 GET，从不发帖、点赞、关注）
  - `https://www.douban.com`（豆瓣条目评论的公开 RSS `/feed/subject/<ID>/reviews`，只发 GET；你在 2026-10-31 同意加入）
  - `https://i.ytimg.com`（结果卡缩略图）
  - `https://img1.doubanio.com` … `https://img9.doubanio.com`（豆瓣条目海报，只能作为图片加载，不能发其他请求）

| 你看到的提示 / 现象 | 原因 | 怎么办 |

| 授权窗口显示 "Error 403: access_denied" / "Access blocked" | 你登录的 Gmail 不在测试用户列表里（或加在了别的 Google Cloud 项目里） | 回到 [1.2](#install) 的第 4 小步添加测试用户；核对项目编号与 Client ID 开头的数字一致 |

| 授权窗口显示 "Error 401: invalid_client" / "OAuth client was not found" | Client ID 填错，或用的是旧的"Chrome 扩展程序"类型客户端 | 按 [1.2](#install) 第 6 小步新建"Web 应用"客户端，换进 `local/config.json` → `npm run build` → 刷新扩展 |
| "授权没有完成" | 你关掉了授权窗口，或 Google 在窗口里显示了上面某个错误 | 按窗口里的错误对照上面几行；没有错误就再点一次 **连接 YouTube** |

## 🔄 更新、备份与卸载

- **更新代码后**：`git pull` → `npm install` → `npm run build` → `chrome://extensions` 刷新 TubeMuse → **刷新已打开的 YouTube 标签页**。
- **用的是 Releases 上下载的安装包**（[1.0](#download)）：下载新版本的 .zip，解压覆盖到原来的文件夹 → `chrome://extensions` 刷新 TubeMuse → 刷新已打开的 YouTube 标签页；Firefox 临时载入新的 .xpi。
- **备份**：设置页 **导出全部数据（JSON）**；学习总结可以在 **记录** 页 **导出记忆库（Markdown）**。
- **换电脑**：把项目文件夹连同 **`local/`** 一起复制过去（这样扩展 ID 不变、OAuth 客户端照常可用），再执行 `npm install` → `npm run build` → 加载 `dist`。导出的数据目前不能导回，需要重新同步画像。
- **撤销 Google 授权**：设置页 → **断开**；也可以在你的 Google 账号 → 安全性 → 第三方访问里移除 TubeMuse。
- **卸载**：在 `chrome://extensions` 移除 TubeMuse，扩展保存在浏览器里的数据会一并删除，建议先导出。

npm run verify      # 以上全部（.crx 的安装冒烟只在 CI 的 Linux 上跑，见下面"自动发布"）

- **测试不出网**：单测把全局 `fetch` 换成直接报错的函数，所有外部服务都用注入的假实现；e2e 把所有外部服务指向本机 mock（127.0.0.1:47321），其他任何请求都会被拦截并判失败。
- **仓库里不放像 Key 的字符串**（[DECISIONS.md](DECISIONS.md) §73）：真 Key 只在设置页填、只存本机。测试要用像 Key 的假值（例如验证脱敏）时，用 `tests/unit/fake-secrets.ts` 的 `fakeSecret('sk-proj-', 'test…')` 在运行时拼出来——整串写在源码里的话，GitHub 的密钥扫描分不出真假，会当成真 Key 报"已公开泄露"。`npm test` 会把仓库里每个文件（已提交的，加上没提交也没被 `.gitignore` 忽略的）按 `scripts/secret-patterns.mjs` 的格式查一遍，查到就失败，只报文件、行号和开头几个字符。
- **CI**：指向 `main` 的 PR 和 `main` 上的 push 都由 GitHub Actions（[.github/workflows/ci.yml](.github/workflows/ci.yml)）在 Windows 上跑和 `npm run verify` 同一套检查：类型检查、单元测试、e2e、正式版冒烟，以及 Firefox 版的 e2e 与安装包冒烟（这一个 job 在 Ubuntu 上跑）。为了快，CI 把它们拆成几个 job 同时跑（类型检查 + 单测 + 冒烟一个，e2e 每组一个，Firefox 一个，发布用安装包的打包与 `.crx` 安装冒烟一个），最后由 `verify` 汇总，全部通过才算过。合并进 `main` 后的那一次：文件树和 PR 里验过的一模一样时不重跑，运行摘要里写明是哪一次运行验过的；不一样（例如验完以后 `main` 又进了别的改动）就照常全跑。CI 不需要任何 Secret，扩展密钥在 runner 上临时生成（只有发布要 `CRX_PRIVATE_KEY`，见下）。`main` 有分支保护：`verify` 不通过不能合并，也不能直接 push，管理员不例外。提交前先在本地跑 `npm run verify`。失败时的截图在这次运行的 Artifacts 里（每组一份），保留 7 天。分组与取舍见 DECISIONS §61。
- **自动发布**（[.github/workflows/release.yml](.github/workflows/release.yml)，[DECISIONS.md](DECISIONS.md) §70）：每次有改动合并进 `main`，`main` 上的 CI 一通过（这棵文件树在 PR 里验过时只要十几秒），就跑 `npm run package` 打出 Chrome 的 `.zip` / `.crx` 和 Firefox 的 `.xpi`，让真的 Chromium 按策略下载、校验、安装一遍这个 `.crx`，然后发布到 [Releases](https://github.com/Anna-SAP/TubeMuse/releases)：标签 `v<版本>`，版本号是 `package.json` 的版本加上这个提交在 `main` 上的提交数（例如 `0.1.0.137`，只增不减）。说明里写着扩展 ID、授权回跳地址和安装方法，后面附上自上一版以来合并的 PR。也可以在 Actions → **Release** → **Run workflow**（分支选 `main`）手动发布当前的 `main`；同一个版本发布过就不再重复。
  - **要先配一个 Secret**：`.crx` 要用私钥签名，`.zip` 里 manifest 的 key 也来自它；用你本机 `local/extension-key.pem` 签，装上后的扩展 ID 就和你自己构建的一样，Google Cloud 不用改。到仓库 **Settings → Secrets and variables → Actions → New repository secret**，名字 `CRX_PRIVATE_KEY`，值粘贴 `local/extension-key.pem` 的全文（`-----BEGIN PRIVATE KEY-----` 到 `-----END PRIVATE KEY-----`）。没配时发布失败，运行摘要里写明要怎么做；配好后对那次运行点 **Re-run jobs**，或手动运行一次。私钥只交给发布工作流里载入它的那一步，只写在那台 runner 上；构建脚本会检查安装包里没有私钥。
  - PR 上的 CI 多一个 `package` job：用 runner 上临时生成的密钥把同一条打包路走一遍（包括 Chromium 安装 `.crx`），`verify` 要它也通过，免得合并后才发现发布不出来。本地跑这个冒烟要 Linux：`node tests/e2e/smoke-crx.mjs`，策略目录 `/etc/opt/chrome_for_testing/policies/managed` 要能写。
  - **Firefox 版交给 Mozilla 签名**（[DECISIONS.md](DECISIONS.md) §71）：发布之后，`scripts/sign-firefox.mjs` 用 Mozilla 官方的 `web-ext sign --channel=unlisted` 把这一版交给 addons.mozilla.org 签名（**自行分发，不公开上架**），连同这个提交的源码包和给审核员的构建说明（代码是 esbuild 打包过的，Mozilla 要求附源码）。签好后核对（有 Mozilla 的签名文件、其余文件和我们打的 `.xpi` 逐个字节相同——`manifest.json` 会被 Mozilla 重新排版，按解析后的内容比——ID 与版本对得上），以 `tubemuse-<版本>-firefox-signed.xpi` 追加到同一个 Release，Firefox 正式版 / Beta 能永久安装。凭据是 Secret `AMO_JWT_ISSUER` / `AMO_JWT_SECRET`（在 addons.mozilla.org → Developer Hub → [Manage API Keys](https://addons.mozilla.org/developers/addon/api/key/) 拿），只交给签名那一步。签名一般几分钟，最多等 25 分钟；失败或超时这一步变红并写明原因，已经发布的文件不受影响。同一个版本号在 Mozilla 那边只能提交一次：等不到的那一版，签好后到 [AMO 开发者中心](https://addons.mozilla.org/developers/addons) 下载。`web-ext` 单独放在 `tools/amo`（自己的锁文件，不进扩展、不影响主项目的 `npm ci`）。PR 上的 `package` job 还会用它跑一遍 Mozilla 的校验（`npm run lint:firefox`），并对着本机的假 AMO 把签名流程走一遍（`npm run test:sign`，不连 Mozilla）。
- **Firefox 的 e2e**（[DECISIONS.md](DECISIONS.md) §69）：用 Firefox 自带的 Marionette 协议驱动（`tests/e2e/firefox/marionette.mjs`，不需要 geckodriver），以临时附加组件装上 `dist-firefox-e2e/`，同样用本机 mock，Firefox 的代理指向一个不存在的端口，除本机外的请求一律出不去。要一个 Firefox 149 或更新：环境变量 `FIREFOX_BIN` 指向它，或装在常见位置（Windows 的 `C:\Program Files\Mozilla Firefox\`、macOS 的 `/Applications/Firefox.app`、Linux 的 `/usr/bin/firefox`）；它另开一个临时配置的无头 Firefox，不碰你平时用的那个。Linux 上没有声音设备时无头 Firefox 的 AudioContext 起不来（录制、自动字幕要用），先起一个 PulseAudio 空设备（CI 里就是这么做的，见 ci.yml 的 `firefox` job）。CI 上 Firefox 版本钉在 161.0b2。
- `dist-e2e/` 是测试专用构建（Google 授权页与所有接口都指向本机 mock），**不要**在日常浏览器里加载它。`dist-firefox-e2e/` 同理。e2e 会真实调用 `launchWebAuthFlow`，走完"弹窗 → mock 授权页 → 回跳授权码 → mock 令牌端点换令牌（校验 Client Secret 与 PKCE）"的整条链路，并验证访问令牌过期 24 小时后、浏览器重启后都能用刷新令牌自动续期。正式构建 `dist/` 的构建脚本会自检：产物里出现疑似 Key、令牌或测试地址就构建失败。
- 技术栈：TypeScript（strict）· esbuild · Preact · Vitest · Playwright（Chromium）· Firefox 自带的 Marionette；大模型用 Anthropic / OpenAI 官方 SDK。
- 关键设计与取舍（为什么这样选、放弃了什么、以后怎么替换）见 [DECISIONS.md](DECISIONS.md)；产品规格见 [CLAUDE.md](CLAUDE.md)。

## ⚠️ 已知限制

- 画像只来自订阅、喜欢的视频、本扩展记录的观看，以及可选导入的 Takeout 历史（YouTube API 不提供观看历史）。
- **Releases 上的安装包**（[DECISIONS.md](DECISIONS.md) §70）：Windows / macOS 的正式版 Chrome 不允许安装 Chrome 应用商店以外的 `.crx`（Google 的规定，绕不开），这两个系统用 `.zip`。`-firefox-signed.xpi` 由 Mozilla 签名、能永久安装，但发布后要等 Mozilla 签完（一般几分钟）才出现；Mozilla 之后也可能随时人工复查这些版本。未签名的 `.xpi` 只能临时载入。安装包里不带 OAuth Client ID，装好后在设置页填一次。`.crx` 在自动化测试里由 Chromium 按企业策略实际装过（Linux）；拖进 `chrome://extensions` 的装法没有自动化验证。
- **Firefox 版**（[DECISIONS.md](DECISIONS.md) §69）：自己构建的（未签名）只能临时载入，重启后要重新载入，永久安装用 Releases 上签过名的版本（§71）；语音只能本机识别（这个语言没有本机模型时语音输入用不了，可以打字；自动字幕可改用 OpenAI 转写）；没有本地翻译（自动字幕第二行请用大模型翻译）；片段录成 WebM。自动化测试在 Firefox 161.0b2 里跑过安装、设置、授权（mock）、找片打分、录制、Capture、剪贴板、多语字幕、问 muse、小红书、eMails、自动字幕和侧边栏，但都是在仿页面上；真实的 YouTube、Google 登录页、各站页面，以及 Firefox 本机语音模型下载成功后的识别，以你的实测为准。
- YouTube 授权靠刷新令牌自动续期。Google 应用处于"测试中"时，刷新令牌 **7 天**后失效，要点一次"重新授权"；发布为正式版可去掉这个期限（见 [可选：发布为正式版](#oauth-production)）。后台定时任务（如 23:00 的总结补元数据）在续期失败时会记录原因并提示，不会静默跳过。
- 换授权码、续期都要带 Client Secret（Google"Web 应用"客户端的要求），所以要在设置页填一次。它只存在本机，只发往 `oauth2.googleapis.com/token`。
- 自动化测试只在 Playwright 自带的 Chromium 里跑过；Comet 等其他 Chromium 浏览器没有自动化验证（`launchWebAuthFlow` 是标准扩展 API，按理可用，以你的实测为准）。
- Comet 上以前的自动续期一直不成功（Google 回 `interaction_required`）：那是旧做法（隐藏窗口 + `prompt=none`）的问题，2026-11-07 已改为刷新令牌，续期不再经过浏览器窗口（[DECISIONS.md](DECISIONS.md) §53）。新做法在 Comet 上的实测以你的手测为准。
- "形式""质量"无法从 API 元数据可靠判断，只能按标题/简介关键词、播放量与点赞率近似——回显里会如实标注"近似落实"。
- 语言判断优先用视频的音频/默认语言元数据；缺失时按标题文字推断（会标"按标题推断"）。拉丁语系之间无法靠文字区分。
- 广告识别依赖 YouTube 播放器当前的页面结构（`ad-showing` 标记）；YouTube 改版后可能识别不到，届时广告时间会被算进有效观看（完成率不受影响）。
- 时长不足 30 秒的视频即使看完也算"瞥一眼"（按"有效观看 < 30 秒 = 瞥一眼"的规则）；阈值可改。
- 追踪只在桌面版 `www.youtube.com` 上工作；不覆盖 YouTube Music、嵌在其他网站里的播放器、手机或电视。
- 大模型默认模型的分工（总结、周报、热点、eMails 用 `claude-haiku-5-5`）没有用真实调用比较过质量；不满意的话在设置页 **1.** 把那一项改回主模型。
- Chrome 本地翻译：质量一般，只翻当前这一句、没有上下文；只在 Google Chrome 138 及以上验证过接口。Comet 等其他 Chromium 浏览器不一定下载得了语言包，下载失败时请改用大模型翻译。语言包要下载；下载后在扩展后台能不能用，自动化测试验证不了（测试用的 Chromium 下不了语言包），见打卡清单。
- 片段录制认不出 X 的片头广告：判断它需要读 X 播放器的内部标记，还没有在真实广告上核实过，所以不做猜测，界面上写明，等广告放完再开始录。
- 酷播的片头广告只认得出一种：2026-11-10 在真实页面上看到的那条（20 秒的 VIP 宣传片）和正片用同一个播放器放，正片是 `blob:` 流，它是直接给地址的短片。TubeMuse 就按"不是 `blob:` 流、又不超过 2 分钟"来认，样本只有这一条：别的形式的广告（例如叠在画面上的、做进正片流里的）认不出来，会被录进去；反过来，如果有正片恰好是直接给地址的短片，会被当成广告一直不录（**片段** 页会一直写"广告中"）。两种情况碰到了请告诉我。
- X 热点来自"用兴趣关键词检索的高互动帖子"，不是 X 的全站趋势榜（那与兴趣无关，也没有原文链接）；与你兴趣无关的大事件不会出现。
- "跟随当前标签页"只认 `www.douban.com` 上的地址（评论 RSS、`www.douban.com/subject/<ID>/`）。`movie.douban.com` 等子域名上的条目页看不到网址，不会跟随——要支持得给扩展加这些子域名的权限，属于网络出口红线的变更，没有擅自加。

- **中文配音**（[DECISIONS.md](DECISIONS.md) §74、§75、§77）：只跟随播放状态加手动偏移 / 对齐点；中文与原视频长度、停顿不同（还可能删了段落），要靠对齐点分段对齐，对齐点之间仍可能有一两秒的出入，对齐点越密越准。对齐点要自己一个个加，没有自动找。配音开着时录的片段是固定比例的双语混音（原声 80% + 中文 100%），不是你此刻音量条下的绝对音量；叠出来的峰值经软限幅压在满幅以内。对齐图（§77）只画出跟随本来的规则：色带表示"这一段中文在这一段视频里按正常速度放"，不表示句子对上了；播放头在两次读位置之间（每秒一次）是推算的，拖进度条后最多晚一秒跟上；不画真实波形（英文原声拿不到：不下载 YouTube 的音视频）。

- 多语字幕：
  - 字幕文字来自 YouTube 播放页自己的字幕接口（`/api/timedtext`），不是有文档的公开接口：官方 Data API 的 `captions.download` 只给能编辑这个视频的人用，还要 `youtube.force-ssl` 权限（2026-11-02 核实）。YouTube 改动字幕接口或令牌（`pot`）的规则时会取不到，届时会停下并说明，不会静默显示为空。
  - 拿令牌要等播放器发出一次字幕请求：原生字幕关着时，TubeMuse 会请播放器短暂打开一次字幕（可能闪一下），YouTube 会把这条轨记成你下次按 `C` 时的默认语言。
  - YouTube 在视频（或广告后的正片）开始后约 1 秒会按你保存的偏好自动打开字幕。为了不把这当成你按了 `C`，正片播放满 2 秒（最多 8 秒）之内被打开的原生字幕一律当作播放器打开的：照常关掉，关闭多语字幕时恢复。所以视频刚开始的那 2 秒里你按 `C`，会被关掉一次；再按一次即可。原生字幕本来关着、又是在视频刚开始时开启的话，多语字幕会晚 2 秒左右出现。
